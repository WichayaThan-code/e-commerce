# ThaiShopFun — Project Hub

ชุดเอกสารวางแผนและติดตามงานสำหรับ Notion • ตรวจจาก source code วันที่ 17 กันยายน 2026

## เริ่มใช้งาน

1. แตกไฟล์ `ThaiShopFun-Notion.zip` ก่อน
2. ใน Notion บน desktop/web ไปที่ Settings → Import → Text & Markdown แล้วเลือกไฟล์ `.md` ในชุดนี้
3. สร้างหน้า ThaiShopFun Project Hub แล้วนำหน้าที่ import มาไว้ใต้หน้าเดียวกัน
4. เปิด 01-Task-Project-Tracking แล้วใช้ตารางงานเป็นรายการตั้งต้น สร้าง database ตาม property ที่ระบุและคัดลอกงานเข้าไป
5. เก็บไฟล์ `.sql` เป็นไฟล์แนบ หรือใช้ code block จากหน้า 04-PostgreSQL-Queries

Markdown นำเข้าเป็นหน้าเอกสาร ตารางใน Markdown ไม่ได้สร้าง database แบบมี Status, Relation, Rollup, Board หรือ Formula ให้โดยอัตโนมัติ ต้องตั้งค่าตามคู่มือหลัง import ชุดนี้ยังไม่ได้สร้างหน้าในบัญชี Notion ของคุณ

อ้างอิงการนำเข้า: [Notion Import](https://www.notion.com/help/import-data-into-notion)

## สารบัญ

- 01-Task-Project-Tracking: แผนงาน รายการงานตั้งต้น และวิธีตั้งค่า database
- 02-Project-Documentation: สถาปัตยกรรม ขอบเขต ระบบ API และฐานข้อมูล
- 03-Tools-and-Runbook: เครื่องมือ คำสั่งรัน ทดสอบ สำรองและกู้คืน
- 04-PostgreSQL-Queries: query ตรวจข้อมูลและสุขภาพฐานข้อมูล พร้อมคำอธิบาย
- 05-Templates: แบบฟอร์มงาน บั๊ก เอกสาร การตัดสินใจ และรายงานรายสัปดาห์
- 06-OMS-Product-Vision: ตำแหน่งธุรกิจ กลุ่มเป้าหมาย และขอบเขตฟีเจอร์ OMS
- sql/readonly.sql: query แบบอ่านข้อมูลอย่างเดียว

## ภาพรวมปัจจุบัน

ThaiShopFun ขาย "ระบบ" OMS (Order Management System) ให้ร้านค้าออนไลน์ไทย ไม่ได้ทำแพลตฟอร์มมาแข่งกับ Shopee/TikTok — รายละเอียดตำแหน่งธุรกิจและกลุ่มเป้าหมายอยู่ที่ 06-OMS-Product-Vision ใช้ React + TypeScript + Vite, Spring Boot (Java 17), PostgreSQL และ Flyway

พบ implementation สำหรับระบบสมาชิกและการสมัครร้านค้า พร้อมไฟล์ integration tests แต่การจัดเอกสารครั้งนี้ไม่ได้รันทดสอบระบบหรือเชื่อมฐานข้อมูลจริง จึงไม่ระบุว่างานเหล่านั้น Done

โฟลเดอร์ frontend มีหน้าร้านค้า สินค้า ออเดอร์ และแอดมินหลายหน้า ซึ่งปัจจุบันเขียนในโครงหน้าตาแบบ marketplace ที่ร้านค้าสมัครเข้ามาขาย — ต้องพิจารณาปรับให้สะท้อนว่าเป็นหน้าร้าน (storefront) ของร้านแต่ละรายที่ผูกกับ OMS ไม่ใช่ตลาดกลางที่แข่งกับแพลตฟอร์มอื่น การมีหน้า UI ไม่ได้ยืนยันว่ามี backend ครบแล้ว ฐานข้อมูลตาม migration ที่ตรวจมี 4 ตารางธุรกิจ และยังไม่มีตารางสินค้า ออเดอร์ การรวมออเดอร์ข้ามแพลตฟอร์ม หรือชำระเงิน

## กติกาทีม

- ทุกงานมีผู้รับผิดชอบ เกณฑ์ตรวจรับ และลิงก์หลักฐานก่อนเปลี่ยนเป็น Done
- วันที่เริ่ม กำหนดส่ง และผู้รับผิดชอบเว้นให้ทีมตกลง ไม่ได้สมมติเป็นแผนที่อนุมัติแล้ว
- อัปเดตสถานะเมื่อมีความคืบหน้า; ทบทวนงานค้างและสิ่งกีดขวางทุกสัปดาห์
- เก็บเฉพาะข้อมูลตัวอย่างใน Notion ไม่วางรหัสผ่าน token หรือข้อมูลระบุตัวตนลูกค้าจริง
